## 3. 将改动提交到自己的分支

对于文档变更，可以直接在自己 fork 的网页中操作：进入仓库后点击 **Add file → Create new file**，填写文件路径与复测内容，预览后点击 **Commit changes**。选择为此次改动创建新分支，例如 `review/cai-smoke-check`。后续相关改动提交到同一分支。操作参考 [GitHub：Creating new files](https://docs.github.com/en/repositories/working-with-files/managing-files/creating-new-files)。

提交说明写清本次变化，例如 `docs: 补充独立复测记录并明确完成状态的查看方法`；示例只适用于实际做了对应改动的情况。若修改程序代码，按实际功能划分提交，并复跑相关检查。

单元测试可以保留在仓库。题目写的是“不必上传”，并未要求删除已有测试。
